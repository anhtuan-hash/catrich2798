# Attendance Material 3 + Monthly Reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign the attendance module as a Material 3 Android-tablet workspace and add lesson-period tracking, cancelled sessions, monthly reporting, and Excel/PDF export.

**Architecture:** Keep `GlobalAttendanceNavigationTab.jsx` as the portal/shell and shared state owner, but move monthly report aggregation/export into focused utilities/components. Extend the existing Supabase attendance session model and confirmation RPC so completed and cancelled sessions share the same class/date lock. Implement exports without new npm dependencies: true `.xlsx` is generated by a small no-compression ZIP/XLSX writer, while PDF uses a print-only HTML document and the browser Save-as-PDF flow.

**Tech Stack:** React 18, Vite, Supabase/Postgres RPC + RLS, plain scoped CSS, Node contract tests, Playwright Critical E2E.

**Spec:** `docs/superpowers/specs/2026-09-08-attendance-material3-reporting-design.md`

## Global Constraints

- Scope is only `Điểm danh lớp phụ đạo & bồi dưỡng`; do not restyle the rest of Brian English.
- Remove the exact header copy `Mỗi lớp chỉ chốt một lần mỗi ngày · giờ xác nhận lưu theo máy chủ`.
- Preserve unique `(class_id, attendance_date)` locking for both completed and cancelled sessions.
- Completed `lesson_periods` must be exactly `1`, `1.5`, or `2`; cancelled sessions must store `0`.
- Cancelled sessions require a reason, create no per-student attendance records, and contribute zero periods.
- Multi-teacher completed sessions require a teacher from normalized class assignments, including manually-added teachers.
- Writes remain Admin-only; new RPCs use `SECURITY DEFINER`, `set search_path = public`, explicit `can_manage_extra_class_attendance()`, revoke `public/anon`, grant `authenticated`.
- Existing class/member/manual-teacher/delete-session behavior must remain intact.
- Use TDD for behavior/data changes and keep Frontend Build, Critical E2E, and Supabase guards green before merge.

- [ ] **Step 3: Implement migration**

Migration requirements:

```sql
alter table public.bes_extra_attendance_sessions
  add column if not exists session_status text not null default 'completed',
  add column if not exists lesson_periods numeric(3,1) not null default 1,
  add column if not exists cancellation_reason text not null default '';

alter table public.bes_extra_attendance_sessions
  drop constraint if exists bes_extra_attendance_sessions_status_check,
  add constraint bes_extra_attendance_sessions_status_check
    check (session_status in ('completed','cancelled')),
  drop constraint if exists bes_extra_attendance_sessions_periods_check,
  add constraint bes_extra_attendance_sessions_periods_check
    check ((session_status='completed' and lesson_periods in (1,1.5,2))
        or (session_status='cancelled' and lesson_periods=0));
```

Replace the completed-session RPC with the new `p_lesson_periods numeric` argument. Validate allowed values and normalized teacher membership before insert. Preserve existing server timestamp, class/date lock, and student-record insertion.

Create `bes_cancel_extra_class_session(p_class_id uuid, p_attendance_date date, p_cancellation_reason text)` that validates Admin/date/reason, inserts a session snapshot with `session_status='cancelled'`, `lesson_periods=0`, counts `0`, teacher blank, and creates no attendance records.

Revoke `public` and `anon`; grant only `authenticated` for both new signatures.
